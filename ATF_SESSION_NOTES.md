# ATF Framework — Session Notes

Working notes from building the ATF (Agent Trajectory Fidelity) evaluation framework and
two real integrations. Written so the session can be picked up later without re-deriving
context. Original draft spec: `ATF_Metric_Definition_Evaluation_Specification.md` (this
folder; superseded by the frozen `METRICS.md` alongside it — see §3.5 below).

## 1. What got built

### `atf_eval/` — the framework itself

Standalone project, own venv, own `pyproject.toml` (name `atf-eval-poc`, console script
`atf-eval`). Zero LLM dependency — every ATF metric is a closed-form formula. Only
dependency: `pydantic`.

```
atf_eval/
  src/atf_eval/
    normalized.py     NormalizedTurn/Node/StateChange/ToolCall/Routing/Outcome (the adapter contract)
    dataset.py         GoldenTurn (pydantic) + load_dataset() + group_by_conversation()
    adapter.py          TrajectoryAgent Protocol — run_turn(conversation_id, turn_id, user_input, history)
    loader.py            load_adapter("module:Class") dynamic import
    lcs.py                 shared normalized-LCS order-similarity utility
    matching.py            numeric-tolerance value comparator (shared by TIS + OS)
    aggregate.py            weighted_composite / aggregate_turns / atf_score + DEFAULT_WEIGHTS
    metrics/                nodes.py state.py tools.py routing.py outcome.py — the 5 metric groups
    runner.py                 orchestration; ConversationResult now carries .expected_turns/.observed_turns
    report.py                  aggregate() + write_reports() -> report_<ts>.json/.csv
    cli.py                      `atf-eval run` (argparse)
    diagnostics.py               find_key_state_deviation / find_key_tool_deviation
    scorecard.py                  render_scorecard() — the ATF+Policy text report
    policy/                        rules.py, checker.py, helpers.py — Policy Compliance (separate from ATF)
  examples/               bundled mock adapter + tiny golden dataset (no API key needed)
  tests/                  81 tests, all passing (pytest tests/ -v)
```

CLI:
```bash
atf-eval run --dataset PATH --adapter MODULE:CLASS --output-dir DIR
  [--weights-file weights.json] [--tool-arg-tolerance 0.0] [--limit N] [--concurrency N]
```

Default weights: `NTS=0.30 STS=0.30 TIS=0.15 RS=0.10 OS=0.15`. Missing metrics report `N/A`
(never 0) and are excluded from ATF's weighted average — `metric_coverage` shows how much
of the score is backed by applicable evidence.

### Policy Compliance + Scorecard (added mid-session, user's idea)

Separate, parallel evaluator — **not** folded into ATF's OS metric. Answers "did the agent
stay within the rules" vs ATF's "did it follow the expected path." Reuses the same
`NormalizedTurn` objects ATF already captured (`ConversationResult.observed_turns`), no
second agent invocation needed.

```python
from atf_eval.policy.rules import PolicyRule
from atf_eval.policy.helpers import tool_calls_named, latest_state_value
from atf_eval.policy.checker import evaluate_conversation
from atf_eval.scorecard import render_scorecard

def my_rule(turn, history, context):
    # return None if OK, or a detail string if violated
    ...

result = evaluate_conversation(conv.observed_turns, [PolicyRule("id", "desc", "critical", my_rule)], context={...})
print(render_scorecard("Scenario name", conv, result))
```

Proven both ways: `test_evaluate_conversation_detects_critical_violation` (unit test, exact
"waived premium with no payment capacity check" case) and the live collections rules below.

## 2. Integration #1 — `collection_agent` (rich, stateful, LLM-backed)

Location: `integrations/collection_agent/` (own venv: `pip install -r easy_agents/requirements.txt` + `pip install -e atf_eval`).

Raw dataset: `easy_agents/agents/collection_agent/eval_dataset/collection_agent_golden_dataset_v3.jsonl`
— 1000 scripts, 22 categories (Pay Now, Promise To Pay, Hardship Discount Accepted,
Verification Failure, Bad Actor, ...), **purely synthetic** (generated by
`generate_golden_dataset_v3.py`, never run through the live agent — its own vocabulary,
e.g. `verification_status`, doesn't literally exist in the live agent's state).

Files:
- `convert_golden_dataset.py --per-category N` — picks N scripts from each of the 22
  categories (breadth over depth) -> `golden_subset.jsonl`. `--per-category 1` = 22 scripts.
- `collection_agent_adapter.py` — `CollectionAgentAdapter`. Handles: live session per
  conversation via `CollectionDebugRuntime`; **backs up + seeds + restores** the agent's
  `data/*.json` (customer/case/policy fixtures not present in the live agent's static
  files) and the entire `runtime/` tree (memory is keyed by fixed `user_code` identity
  like `"user_a"`, not session — cross-run/cross-conversation contamination risk, fixed by
  full backup+wipe+restore); derives `verification_status` (golden-only concept) from
  `identity_verified`/`verified_dob`/`verified_mobile`; reads tool calls from
  `state["tool_observations_history"]` (NOT `state["observations"]`, which is a generic
  mixed bag of plan-review/reflection checkpoints too — this was a real bug, fixed);
  captures the `discount_planning_agent` handoff as a synthetic `ToolCall` since discount
  decisions don't go through a normal tool_execution call.
- `collection_agent_policy_rules.py` — 3 rules: `waiver_allowed_gate`,
  `discount_pct_within_policy_max`, `discount_requires_hardship` (checked against
  `context.policy` from the raw script).
- `run_live_eval.py` — checkpointed runner (writes `results/report_<ts>.json/.csv` after
  **every** conversation, not just at the end — important since a full run takes hours).
- `run_policy_demo.py` — runs ATF + policy together on one script, prints the scorecard.
- `golden_subset.jsonl` — already converted: COLL_TRAJ_0001 (Pay Now), COLL_TRAJ_0121
  (Promise To Pay), COLL_TRAJ_0761 (Verification Success).
- `policy_demo_dataset.jsonl` — COLL_TRAJ_0501 (Hardship Discount Accepted), for the policy demo.

for reporting. This is why the raw blended ATF (0.225) is noticeably lower than the
successful-only mean (0.353): RS/OS take the biggest hit from the 8 failures being scored
as 0 rather than excluded.

## 3. Integration #2 — `discount_planning_agent` (thin, stateless, deterministic)

Location: `integrations/discount_planning_agent/` (lightweight venv, `atf_eval` only —
this agent has no extra deps).

Deliberately chosen as a contrasting example: a 72-line, stateless, single-shot pure
function (`DiscountPlanningAgent.run(handoff_payload) -> dict`, no LangGraph, no nodes, no
tool calls, no persistent state). No existing golden dataset for it (none of the other 6
agents in `easy_agents/agents/` have one either — only `collection_agent` does).

- `golden_dataset.jsonl` — 5 hand-authored cases; `user_input` field repurposed to carry
  the JSON-encoded `handoff_payload` (the agent's only real input). Expected outputs
  computed **by hand** from reading the agent's branching logic.
- `discount_planning_adapter.py` — parses `user_input` as JSON, calls the real function,
  wraps the result as `Outcome` only (honest: no nodes/state/tools/routing to observe).

### Result

**ATF = 1.000, metric_coverage = 15%.** NTS/STS/TIS/RS all `N/A` (correctly — this
component genuinely doesn't expose them); only OS applies. Verified not-trivial by
deliberately corrupting one expected value — ATF dropped to 0.965 as expected.

**Takeaway**: ATF's 5-dimension model is a poor fit for a stateless scoring function like
this one — a plain input/output regression test would suit it better. `metric_coverage`
is what makes that honest instead of silently faking a fuller report.

## 3.5 METRICS.md alignment (2026-08-24) — major rewrite

`atf_eval/METRICS.md` is a **frozen scoring spec** that supersedes the original
`ATF_Metric_Definition_Evaluation_Specification.md` in several material ways. Audited the
implementation against it and found real divergences, then fixed all of them:

- **NTS/STS/TIS overall scores** now computed from the **complete concatenated trajectory**
  (`nodes.nts_conversation`, `state.sts_conversation`, `tools.tis_conversation`), not by
  averaging per-turn scores (Frozen Rule #10). Per-turn scores are still computed and kept
  as diagnostics in the report.
- **STS reformulated**: `0.70×Transition Accuracy + 0.30×Order` (was a 5-component
  formula). Transition Accuracy denominator is now `max(expected, observed)`, not
  `len(expected)`. Key/old/new-value accuracy demoted to diagnostics-only.
- **State is now evaluated per-node** (`NormalizedNode.state_changes[]`), not per-turn —
  nodes are aligned first (new `lcs.align()`, a real LCS backtrack producing matched/missing/
  extra pairs, not just a length), then state changes compared within each aligned pair.
  `GoldenStateChange` gained an optional `node_id` field; when omitted, a change is
  attributed to the turn's last node (documented fallback — neither the raw collection_agent
  dataset nor most live-agent traces expose true per-node causal attribution). Every existing
  adapter (`mock_adapter.py`, `collection_agent_adapter.py`) updated to do the same on the
  observed side, or STS would have silently gone to ~0 across the board.
- **TIS identity/input denominator fixed** to "aligned pairs" (`min(expected, observed)`),
  not total expected calls.
- **RS completely redesigned**: was a deterministic `routing.target`/`routing.path` field
  comparison; is now an **LLM-based semantic judge** (new `judge.py`, mirrors
  `rag_eval.metrics.judge`'s structured-output pattern) — `0.70×semantic + 0.30×order`.
  User explicitly chose "build the real judge" over keeping it deterministic or making it
  opt-in. Needs `ANTHROPIC_API_KEY`; gracefully degrades to order-only (semantic component
  N/A) without one, or with `--no-routing-judge`. `NormalizedTurn` gained a `response: str
  | None` field (the agent's reply text) solely to feed this judge.
- Verified end-to-end with a **real** LLM call against the bundled mock example — found a
  genuine semantic/literal divergence in the process (turn judged "correct" despite
  `routing.target` mismatch, confirming the judge isn't just parroting the old score).
- 95/95 tests passing (14 new: `test_judge.py` + `test_lcs.py` alignment cases +
  `test_nodes/tools_metrics.py` conversation-level cases; `test_state_metrics.py` and
  `test_routing_metrics.py` fully rewritten for the new APIs).

Not yet done from METRICS.md §8 ("every metric result must expose metric_id/score/status/
applicability/coverage/diagnostics"): implemented as a **documented scope reduction**, not
silently skipped — `report.py`/`scorecard.py` already expose most of this (score, status,
per-turn diagnostics), but there's no single `MetricResult` dataclass threaded through every
metric function. Restructuring every metric function's return type for this would be a much
larger blast radius (every function signature, `runner.py`, `report.py`, `scorecard.py`,
`diagnostics.py`, all tests) — flagged for the user rather than done unprompted given the
session was already a large rewrite.
